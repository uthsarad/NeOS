# NeOS repository audit — 2026-11-01

Reviewed commit `e8ec784`, version `2026.10.17`. Scope: repository structure, verification gates, assisted installation, updater, rollback, and release workflow. No runtime code, version, or release settings changed.

## Findings

1. **P1 — Assisted installation aborts during config generation.** `profile/airootfs/usr/local/bin/neos-autoinstall:356` calls Bash `printf` with a format beginning `---` without `--`. Bash treats this as an invalid option; `set -e` terminates apply before the installer launches. Default `AI_KEYBOARD=us` makes this path unconditional for ordinary configurations. Line 359 repeats the defect for locale. Reproduced by loading the functions from the committed script and generating config against a temporary copy of the repository's Calamares configuration. Use `printf --` and test generation, not only parsing.

2. **P1 — Password configuration produces invalid YAML.** The same script at lines 363–368 appends password commands to the end of `modules/shellprocess.conf`. That file ends with the `i18n` mapping, after the `script` sequence. Appending `    - command:` after `    name:` mixes a sequence into a mapping. After bypassing finding 1 in the temporary reproduction, PyYAML rejected the generated file at line 19. Both plaintext and hashed password paths are affected. Insert entries into the actual `script` list using a YAML-aware transformation and validate generated configurations.

3. **P2 — Discovered cidata mounts are not tracked for cleanup.** At `neos-autoinstall:278`, `mnt="$(mount_device "$dev")"` executes the mounting function in a subshell. Its updates to `CIDATA_UDISKS` and `CIDATA_MANUAL` disappear, so subsequent cleanup cannot release those mounts. A stubbed invocation reproduced a returned mount path with zero parent-shell mount records. Run the function in the current shell and return the path through a variable. Also review line 208: `udisksctl unmount -p` expects an object path, but the array stores filesystem mount paths.

4. **P2 — Windows checkout cannot run Linux shell entrypoints directly.** Working-tree shell files contain CRLF; all 57 attempted gates failed to parse in WSL before meaningful validation. Committed files exported with `git archive HEAD` run normally. `.gitattributes` sets language metadata but no LF policy. Add LF checkout rules for Linux scripts and relevant overlay text files; review normalization separately. This is a checkout portability defect, not evidence that Linux CI fails.

## Release-control risk

`.github/workflows/jules-auto-merge.yml:144` and `:150` intentionally merge same-repository PRs with `--admin`, without waiting for successful checks. Since pushes to testing publish releases, a failed audit gate does not necessarily prevent landing release code. This is documented project policy, not an accidental behavior regression. Consider requiring successful gates before publishing, even if integration merges remain automatic.

## Validation and limits

- Ran 57 non-ISO/non-render gates on an isolated Linux export of HEAD: 56 returned zero; `verify_airootfs_structure.sh` timed out at 45 seconds. A zero exit is not equivalent to full validation where a script skips work.
- C#, Go, and Ruby gates used static fallback checks in WSL; Rust and the Arch-only offline-repository path skipped runtime validation. Torrent generation skipped without mktorrent. actionlint was unavailable; ShellCheck passed.
- Separately ran native Windows `go test ./...` in `tools/neosctl`: succeeded, reporting no test files.
- Existing autoinstall verification passed despite findings 1–3: it exercises parsing and source wiring, not configuration generation or mount lifecycle.
- Targeted reproductions used temporary directories and stubbed mounting; no real disks, mounts, packages, or installed-system settings were modified.
- ISO artifact checks and UI rendering were excluded. No ISO build, QEMU boot, interactive install, live update, real Btrfs rollback, current upstream vulnerability scan, or exhaustive file-by-file review was performed.

Full gate output: `reports/audit-2026-11-01-checks.log`.

Recommended order: fix both installer blockers, cover generated YAML and mount lifecycle with behavioral checks, add LF checkout rules, then verify an actual installation and recovery in a disposable VM.
